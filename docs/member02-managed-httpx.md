# Member 02 — Managed HTTPX Transport Integration

**Scope:** Supply a pinned native-async HTTPX runtime composition for the existing Groq provider. Preserve Core Ports & Adapters and the deny-by-default privacy boundary. This milestone is **not** authorization to run live banking benchmarks.

## Dependency governance

- `pyproject.toml` pins `httpx==0.28.1`; the exact transitive wheel/sdist hashes are retained in `uv.lock` generated by GitHub Actions (`uv lock`).
- GitHub CI validates `uv lock --check`, `uv sync --locked`, strict mypy, Ruff, pytest and offline CLI smoke.
- The temporary **read-only** GitHub Actions lock generator was removed before review. No persistent workflow with write permissions or lock content embedded in docs remains.

## SOLID responsibilities

| Layer | Responsibility |
| --- | --- |
| `BenchmarkOrchestrator` | Own retries, provider attempt budgets, run provenance and traces; no HTTPX imports |
| `LLMProviderPort` / `GroqChatProvider` | Existing provider request validation and default-deny privacy approval |
| `HttpxPoolSettings` | Validate connection/pool configuration without carrying credentials |
| `HttpxStreamingClient` | Translate `httpx.AsyncClient.stream()` into narrow async streaming protocol; normalize SDK timeouts to safe `TimeoutError` |
| `AsyncClientGroqTransport` | Fixed endpoint, deny redirects, bounded streamed response, safe Retry-After extraction |
| `managed_httpx_groq_provider()` | Own one shared HTTP client/pool with async context manager and deterministic shutdown |

Client configuration enforces TLS certificate verification, `trust_env=False` (no implicit environment proxies), `follow_redirects=False`, bounded connections and keepalive counts, explicit connection and pool timeouts, and shared lifecycle. The number of open HTTP connections is not configured above `GroqProviderOptions.max_in_flight`.

On HTTPX timeout, `HttpxStreamingClient` raises a safe standard `TimeoutError` instead of exposing exception details. The existing provider emits `GROQ_TIMEOUT` and preserves orchestrator retry caps. Other SDK errors are safely normalized by `GroqChatProvider` as `GROQ_TRANSPORT_ERROR`. `asyncio.CancelledError` is **not caught**; the stream and client are asynchronously disposed.

## Example DI composition (offline only)

```python
import httpx
from llm_routing_eval.adapters.providers import (
    GroqProviderOptions,
    managed_httpx_groq_provider,
)

# No privacy authorization is supplied: provider remains deny-by-default.
async with managed_httpx_groq_provider(
    GroqProviderOptions(allowed_models=frozenset({"openai/gpt-oss-20b"}))
) as provider:
    # Provider remains disabled by default; no Groq calls are issued.
    pass
```

An approved live composition would need `live_enabled=True`, explicit environment opt-in, secret management and a **reviewed per-request** `OutboundAuthorization` implementation. The `groq-preflight` command continues to return BLOCKED pending expert evaluation, privacy and pricing approval.

## Offline verification

`tests/unit/test_managed_httpx_groq.py` uses HTTPX `MockTransport` and in-memory streamed response objects to verify authenticated request construction, fixed endpoint/redirect refusal, connection-context cleanup, a two-call shared pool lifetime, safe timeout classification, denial before HTTP, and coroutine cancellation with response close. It runs without a real socket or Groq credential.

**Important limitation:** Unit tests confirm in-process async cancellation and resource cleanup with HTTPX's mock transport, **not end-to-end socket cancellation under real TLS, DNS, proxy, or network-fault conditions**. Production readiness still needs a separately approved, synthetic-only integration environment with connection termination, pool saturation, cancellation under load, and load/chaos tests. No real customer data should be transmitted before Member 04's security/data-governance sign-off.
