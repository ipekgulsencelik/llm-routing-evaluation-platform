# Member 02 — TLS, DNS and Remote-Disconnect Reliability Tests

**Scope:** Real localhost TLS handshake verification, synthetic DNS resolution failures and abrupt TCP disconnect handling for the pinned HTTPX 0.28.1 native-async Groq runtime. No calls to Groq or other public endpoints and no real banking/customer inputs.

## Security and dependency policy

- The test suite uses `trustme==1.2.1` as a **dev-only** dependency with exact transitive versions and package hashes in `uv.lock`. The package creates ephemeral test certificate authorities and leaf certificates on demand.
- No PEM certificate private keys, fabricated production credentials, credentials supplied by developers or customer data are checked into Git. There are no external DNS queries for the synthetic invalid hostname.
- The temporary **read-only** CI workflow used to regenerate the lock was deleted before PR creation; the normal `uv lock --check` / `uv sync --locked` controls remain mandatory.
- Socket-backed tests bind ephemeral `127.0.0.1` ports exclusively and use short, bounded deadlines and cleanup.

## Failure modes and expected behavior

| Check | Realism and contract | Expected behavior |
| --- | --- | --- |
| Trusted synthetic CA + correct IP SAN | Actual TLS handshake on local TCP socket | Encrypted response succeeds with `CERT_REQUIRED` and hostname checks enabled |
| Untrusted synthetic CA | Actual local TLS handshake | Fails closed with `GROQ_TLS_VERIFICATION_FAILED`, **not retryable** |
| Wrong host SAN with trusted CA | Actual local TLS handshake with wrong certificate hostname | Fails closed with `GROQ_TLS_VERIFICATION_FAILED`, **not retryable** |
| Synthetic `.invalid` DNS failure | Overrides `socket.getaddrinfo` for one fake host; **no real external DNS query** | Safe `GROQ_NETWORK_ERROR`, retryable within existing attempt budget |
| Server closes TCP before response headers | Actual localhost socket | Safe `GROQ_NETWORK_ERROR` without sensitive exception text |
| Server closes TCP mid-response body | Actual localhost socket | Safe `GROQ_NETWORK_ERROR`; incomplete response is not scored as success |
| Core provider error mapping | Synthetic injected transport exceptions | Normalized TLS/network codes, correct retry flags, no key or provider-detail leakage |

## Ports, responsibilities and compatibility

- `HttpxStreamingClient` keeps HTTPX-specific TLS/connection/protocol exception interpretation **outside** Core and transports; `_is_tls_verification_failure` inspects only a bounded exception-type chain, never exception messages.
- `GroqTLSVerificationError` and `GroqNetworkError` are narrow redacted adapter exceptions in the provider transport boundary; `GroqChatProvider` maps them to contract-safe `ModelResponse` errors.
- The orchestrator keeps responsibility for retry limits; permanent certificate validation errors cannot waste model retries. Network disconnects remain retryable and capped by the unchanged per-case attempt budget.
- No Core DTOs, routing strategies, pricing, evaluation rubric, or CLI live-mode changes. Existing `DenyAllOutbound` remains the default.

## How to run

```powershell
uv sync --locked
uv run pytest -q tests/integration/test_httpx_tls_dns_disconnect.py
uv run pytest -q
uv run llm-routing-eval groq-preflight
```

`groq-preflight` is expected to return BLOCKED with exit code 2. CI runs all TLS/DNS tests as part of `pytest` and does not require an actual Groq API key.

## Outstanding enterprise release gates

- The TLS tests exercise **loopback certificates generated by a synthetic CA**, not public CA trust-store updates, certificate revocation or real remote endpoint certificates.
- DNS failure is safely injected (not a real external resolver outage); proxy bypass, split-horizon DNS, DNS rebinding, IPv6, TLS inspection and outbound egress policies need separate infrastructure-level review.
- Connection reset/load/chaos tests at scale and production TLS handshake telemetry still need a controlled synthetic-only staging environment.
- Member 03's expert golden evaluation, Member 04's approved outbound privacy authorization and verified cost/pricing/account access remain mandatory. Never enable live banking benchmarks based only on these tests.
